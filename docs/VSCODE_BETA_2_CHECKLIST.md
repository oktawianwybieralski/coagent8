# Local beta.2 VS Code acceptance

Install the replacement VSIX and record its SHA-256 from the owner's handoff.
CoAgent8 is provided by the extension, so it is listed in MCP: List Servers, not in
the Extensions view's MCP Servers - Installed section, which lists mcp.json and
gallery servers.
These checks require the actual editor; passing fixtures do not establish them.
Record PASS, FAIL or NOT_RUN for each item, with the exact action and observed
result. No test requires deleting vendor extensions, credentials or histories.

| Check | Action | Expected result |
| --- | --- | --- |
| Installation | Install from VSIX in a trusted workspace. If the Extensions view requests Restart Extensions, use that action. | One CoAgent8 extension, the new commands, and no remaining Restart Required after the native action. Record a persistent banner as FAIL; do not hide it with a window reload. |
| Configuration path | In User Settings, search for CoAgent8 and set Config Path to an absolute path with spaces. Run Open Configuration. Then clear the setting and open again. | The first action opens the chosen file; the second opens `~/.coagent8/config.json` (or `coagent8_CONFIG`). New files have defaults. Existing contents survive. |
| VS Code settings | Run CoAgent8: Open Settings. Check every option. Set Default Backend and add a model to Never Ask Models, then call doctor from chat without restarting anything. Then use Reset Setting on both. | Twelve settings under CoAgent8, each with a description and an inline control; none is marked invalid. VS Code restarts the server by itself; doctor reports the chosen default backend and config.json is unchanged. After the reset, the file values apply again. |
| Configuration reset | Run Reset Configuration (config.json), cancel once, then confirm. Run it a second time. | Cancellation changes nothing. Confirmation opens a default config.json and leaves exactly one config.json.backup with the previous contents. VS Code settings are unchanged. |
| Extension page | Open CoAgent8 in the Extensions view. Check the Features tab, categories and tags. | Features lists Settings, Commands, JSON Validation and the MCP server provider. Categories AI and Chat; tags include llm, mcp, mcp-server, model-context-protocol and vibe-coding. The Manifest and Configuration tabs exist only for MCP gallery servers, not for an extension's provider (VS Code source: mcpServerEditor.ts). |
| JSON schema | In the newly created config, request completion and hover over every field, including governance.alwaysAsk and governance.neverAsk. Temporarily enter the wrong type for a known field. Undo the edit. | Completion, hover descriptions and validation work for every field; the configuration returns to valid JSON. |
| First-activation notice | On a first installation with ready CLIs, observe activation, then reload the window. On a profile without a ready CLI, observe the other notice if available. | One notice names the ready CLIs with Set Up CLIs (only when a CLI is missing, signed out or without a CoAgent8 entry) and Show MCP Servers; it does not return after the reload, and no CLI check runs on later starts (CoAgent8 Setup output). Without a ready CLI the notice offers Set Up CLIs once. No model turn runs during readiness checks. |
| Set Up Coding CLIs | Run it with every CLI ready, then with one CLI signed out or missing if available. Use the title-bar Check Again and Show Details buttons. Accept the list once without changes. | The list fills in about a second. Each line shows the CLI's state, whether CoAgent8 is in its chat, and its installation source (VS Code extension, Antigravity download, standalone, npm). Checked lines are exactly the CLIs with CoAgent8 in their chat; accepting unchanged closes without a notice. Check Again refreshes the list; Show Details opens the output without closing the list. |
| CLI chat registrations | In Set Up Coding CLIs check one ready CLI, accept, choose Restart Extensions and ask that CLI's vendor chat for CoAgent8 doctor. Then uncheck it, accept and restart again. | No modal. Each change ends with one notice; Restart Extensions restarts the extensions and keeps the window and chat histories. After adding, the vendor chat lists CoAgent8; after removing, it does not, and the CLI stays installed. Other MCP entries survive. |
| MCP refresh | Start CoAgent8 from MCP: List Servers and call doctor. Change Config Path and call doctor again without restarting anything. | Exactly one server definition and six tools; the server uses the selected file. Other MCP servers remain available. Capture server output if startup fails. |
| Manual MCP definition | If testing a manual registration, use the editor's MCP UI to add it and then remove only that test entry. | The manual definition takes precedence over the extension provider; removal restores the provider. No duplicate CoAgent8 definition. |
| Quiet operation | Run consultation and current-workspace review while typing in another application. Approve model consent only if you choose to spend that turn. | No visible console or focus loss. Record backend/version, completion or timeout, and observed review verdict. BLOCKED/PARTIAL is not review approval. |
| Dependency installation | On a profile without Antigravity CLI (or another CLI), run Set Up Coding CLIs, keep the missing CLI selected and choose Install VS Code Extension. For Antigravity, open its view once. Then sign in with the offered command and Check Now. | The vendor extension installs from the Marketplace without a sync dialog; setup waits until its CLI is found, then offers sign-in; the CLI becomes Ready. The closing notice says CoAgent8 was added to that CLI's chat and offers Restart Extensions; after it, the vendor chat lists CoAgent8. `setup-state.json` in the extension's storage lists the extension under `installedExtensions`; an extension that was already installed is not listed. |
| Complete uninstallation | Install one CLI with Install Standalone CLI beforehand if possible. With CoAgent8 added to the CLI chats, run CoAgent8: Uninstall CoAgent8. Cancel the first confirmation once. Then select a vendor extension CoAgent8 installed, confirm, and decline the second confirmation. Finally repeat and accept both. Choose Quit VS Code, start VS Code, then check the extension folder and storage, `~/.coagent8`, the three CLI configurations and `state.vscdb`. | Only extensions CoAgent8 installed are listed, none preselected; each cancellation changes nothing. After accepting, the registrations are gone at once; the selected vendor extension and CoAgent8 are uninstalled, and the removal commands of a selected standalone CLI wait in the Remove coding CLIs terminal until you press Enter, after which the CLI is no longer found; after the restart no extension folder, storage or CoAgent8 key remains, and `~/.coagent8` holds only `config.json` if it existed. Vendor sign-ins and histories survive; your `coagent8.*` settings and `~/.coagent8/config.json` remain, as VS Code keeps settings. |
| Uninstallation from the Extensions view | Add CoAgent8 to one CLI in Set Up Coding CLIs and use it once from that CLI's chat. Uninstall CoAgent8 in the Extensions view, quit and start VS Code, and check the same locations. Reinstall the VSIX. | The `vscode:uninstall` hook removes the registration, runtime copy, tagged backups and `setup.json` from `~/.coagent8` (the shared-process log shows its JSON) and keeps `~/.coagent8/config.json`; VS Code removes the folder and storage. **Restart Extensions** alone does not finish it. The reinstalled extension behaves like a first installation and uses the kept configuration. |

The one-off reset of historical CoAgent8 IDs in the owner's Default profile is
separate from these checks. Run the prepared offline script only after
closing every VS Code window, from an external PowerShell. It backs up the exact
changed rows and preserves unrelated profile values; it does not delete profile
databases. This session cannot continue inside an editor that has been closed.
